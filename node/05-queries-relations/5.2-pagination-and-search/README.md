# תרגיל 5.2 · עימוד וחיפוש

ממשיך את תרגיל 5.1. `GET /api/recipes` מחזיר עכשיו עמוד אחד ומידע על העימוד:

```json
{ "data": [ ... ], "page": 2, "limit": 10, "total": 100, "totalPages": 10 }
```

| פרמטר | משמעות | ברירת מחדל |
| --- | --- | --- |
| `page` | מספר העמוד, מ-1 | `1` |
| `limit` | פריטים לעמוד, עד 50 (ערך גבוה יותר מוגבל ל-50) | `10` |
| `q` | חיפוש ב-`title`, לא רגיש לאותיות גדולות וקטנות | |

הפרמטרים מתרגיל 5.1 (`difficulty`, `maxTime`, `sort`) עובדים יחד עם אלה.

## הרצה

```bash
docker run -d --name mongo -p 27017:27017 mongo:8   # אם עוד לא רץ
npm install
cp .env.example .env
npm run seed
npm run dev
curl "localhost:3000/api/recipes?page=2&limit=10&q=pasta"
npm test
```

## משתני סביבה

| משתנה | משמעות | דוגמה |
| --- | --- | --- |
| `PORT` | הפורט שהשרת מאזין בו | `3000` |
| `MONGODB_URI` | כתובת המסד | `mongodb://127.0.0.1:27017/recipes` |

## החלטות מרכזיות

- `skip((page - 1) * limit).limit(limit)` מביא עמוד אחד. `countDocuments(filter)` משתמש **באותו filter**, ולכן `total` מתייחס לתוצאות החיפוש ולא לכל האוסף.
- שתי השאילתות לא תלויות זו בזו, ולכן הן רצות במקביל עם `Promise.all`.
- **מיון יציב**: אחרי שדה המיון מוסיפים תמיד `_id: 1`. בלי סדר קבוע, MongoDB לא מתחייב לאותו סדר בין שתי שאילתות, ואותו מתכון יכול להופיע בעמוד 1 וגם בעמוד 2.
- `limit` מוגבל ל-50 בשרת. בלי מגבלה, `limit=1000000` מושך את כל האוסף בבקשה אחת.
- **`escapeRegex`**: את מה שהמשתמש מקליד בונים ל-regex רק אחרי escape. בלי זה, `q=.*` מתאים לכל המתכונים, ודפוס כמו `(a+)+$` יכול לתקוע את המסד (ReDoS). `$options: "i"` הוא מה שהופך את החיפוש ללא רגיש לאותיות.
- `skip` גדול יקר: המסד עדיין עובר על כל המסמכים שמדלגים עליהם. לאוספים גדולים משתמשים ב-cursor pagination (`_id > lastId`), אבל ל-100 מתכונים `skip` מספיק.
