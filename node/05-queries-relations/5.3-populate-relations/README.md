# תרגיל 5.3 · קשרים עם populate

שני אוספים: `authors` ו-`books`. כל ספר שומר את ה-`_id` של הסופר שלו.

## הרצה

```bash
docker run -d --name mongo -p 27017:27017 mongo:8   # אם עוד לא רץ
npm install
cp .env.example .env
npm run dev
npm test
```

## משתני סביבה

| משתנה | משמעות | דוגמה |
| --- | --- | --- |
| `PORT` | הפורט שהשרת מאזין בו | `3000` |
| `MONGODB_URI` | כתובת המסד | `mongodb://127.0.0.1:27017/library` |

## הנתיבים

| Method | נתיב | פעולה | Status |
| --- | --- | --- | --- |
| GET | `/authors` | כל הסופרים | 200 |
| GET | `/authors/:id` | סופר אחד | 200 / 404 |
| POST | `/authors` | יצירת סופר (`name`) | 201 / 400 |
| GET | `/authors/:id/books` | הספרים של הסופר | 200 / 404 |
| DELETE | `/authors/:id` | מחיקת סופר | 204 / 404 / 409 |
| GET | `/books` | כל הספרים, עם שם הסופר | 200 |
| GET | `/books/:id` | ספר אחד, עם שם הסופר | 200 / 404 |
| POST | `/books` | יצירת ספר (`title`, `author`) | 201 / 400 |

## החלטות מרכזיות

- **reference ולא embedding**: הסופר נשמר באוסף משלו, והספר מחזיק רק את המזהה (`type: ObjectId, ref: "Author"`). שם הסופר נמצא במקום אחד, ותיקון שלו מגיע לכל הספרים.
- `populate("author", "name")` מחליף את המזהה במסמך הסופר. הארגומנט השני מגביל את השדות, כך שחוזרים רק `_id` ו-`name`. מאחורי הקלעים זו שאילתה שנייה (`Author.find({ _id: { $in: [...] } })`), לא JOIN.
- **ל-MongoDB אין foreign keys.** `ref` הוא רק הוראה ל-Mongoose. המסד לא בודק שהסופר קיים, ולא מונע מחיקת סופר שיש לו ספרים. את שתי הבדיקות עושים בקוד: `Author.exists` לפני יצירת ספר (400), ו-`Book.exists` לפני מחיקת סופר (409).
- `GET /authors/:id/books` היא שאילתה על `books` לפי השדה `author`. בגלל זה יש על השדה `index: true`; בלי אינדקס זו סריקה של כל האוסף.
- `409 Conflict` במחיקה: הבקשה תקינה, אבל המצב הנוכחי לא מאפשר אותה. הלקוח יודע שעליו למחוק או להעביר קודם את הספרים.
