# תרגיל 6.3 · בעלות על משאב

ממשיך את תרגיל 6.2. מודל המתכונים הועתק מתרגיל 4.3, ונוסף לו `owner`.

| Method | נתיב | הרשאה | Status |
| --- | --- | --- | --- |
| GET | `/api/recipes` | ציבורי | 200 |
| GET | `/api/recipes/mine` | מחובר | 200 / 401 |
| GET | `/api/recipes/:id` | ציבורי | 200 / 400 / 404 |
| POST | `/api/recipes` | מחובר; `owner` הוא המשתמש המחובר | 201 / 400 / 401 |
| PATCH | `/api/recipes/:id` | רק הבעלים | 200 / 400 / 401 / 403 / 404 |
| DELETE | `/api/recipes/:id` | רק הבעלים | 204 / 401 / 403 / 404 |

נתיבי `/auth/*` זהים לתרגיל 6.2.

## הרצה

```bash
docker run -d --name mongo -p 27017:27017 mongo:8   # אם עוד לא רץ
npm install
cp .env.example .env
npm run dev
npm test
```

## משתני סביבה

| משתנה | משמעות | דוגמה |
| --- | --- | --- |
| `PORT` | הפורט שהשרת מאזין בו | `3000` |
| `MONGODB_URI` | כתובת המסד | `mongodb://127.0.0.1:27017/auth` |
| `JWT_SECRET` | המפתח שחותם על ה-tokens | מחרוזת אקראית ארוכה |
| `JWT_EXPIRES_IN` | תוקף ה-token | `1h` |

## החלטות מרכזיות

- **401 מול 403**: 401 פירושו שלא ידוע מי אתה (אין token, או שהוא לא תקין). 403 פירושו שידוע מי אתה, אבל אסור לך לבצע את הפעולה. `requireAuth` מחזיר 401, ו-`requireOwner` מחזיר 403.
- **`owner` מגיע רק מה-token**: ב-POST הוא נקבע אחרי ה-spread של `req.body`, וב-PATCH הוא מוסר מהגוף. בלי זה, משתמש היה יכול ליצור מתכון בשם מישהו אחר או להעביר מתכון של עצמו למשתמש אחר.
- `requireOwner` הוא middleware שטוען את המתכון, בודק בעלות ושם את המתכון ב-`req.recipe`. ה-PATCH וה-DELETE משתמשים בו, ולא קוראים את המתכון פעמיים.
- `recipe.owner.equals(req.user._id)` ולא `===`: אלה שני אובייקטי `ObjectId`, ו-`===` משווה הפניות לאובייקטים ולא ערכים.
- ב-PATCH משתמשים ב-`set` ו-`save` במקום `findByIdAndUpdate`, כי המסמך כבר נטען לבדיקת הבעלות. `save` מריץ את כל הוולידציות של הסכמה, ולכן `title: "א"` מחזיר 400.
- `/mine` נרשם לפני `/:id`. אחרת Express מתאים את `mine` ל-`:id`, ו-`findById("mine")` מחזיר CastError.
