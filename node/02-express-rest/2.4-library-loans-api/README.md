# תרגיל 2.4 · API לספרייה עם השאלות

## הרצה

```bash
npm install
cp .env.example .env
npm run dev
npm test
```

## משתני סביבה

| משתנה | משמעות | דוגמה |
| --- | --- | --- |
| `PORT` | הפורט שהשרת מאזין בו | `3000` |

## הנתיבים

| Method | נתיב | פעולה | Status |
| --- | --- | --- | --- |
| GET | `/books` | כל הספרים, עם `available` | 200 |
| GET | `/books/:id` | ספר אחד | 200 / 404 |
| POST | `/books` | יצירת ספר (`title`, `author`) | 201 / 400 |
| GET | `/members` | כל החברים | 200 |
| GET | `/members/:id` | חבר אחד | 200 / 404 |
| POST | `/members` | יצירת חבר (`name`) | 201 / 400 |
| GET | `/members/:id/loans` | ההשאלות הפעילות של החבר | 200 / 404 |
| POST | `/loans` | השאלת ספר (`bookId`, `memberId`) | 201 / 400 / 404 / 409 |
| POST | `/loans/:id/return` | החזרת ספר | 200 / 404 / 409 |

## החלטות מרכזיות

- השאלה היא משאב בפני עצמו (`loans`) עם `returnedAt`, ולא דגל `isLoaned` על הספר. כך נשמרת היסטוריה, וגם "השאלות פעילות" וגם "האם הספר זמין" הן אותה בדיקה: `returnedAt === null`.
- `available` לא נשמר על הספר. מחשבים אותו בכל קריאה מתוך ההשאלות, כך שאין שני מקורות אמת שיכולים לצאת מסונכרנים.
- `409 Conflict` פירושו שהבקשה תקינה אבל מתנגשת במצב הנוכחי (הספר כבר מושאל, או כבר הוחזר). `404` פירושו שהספר או החבר לא קיימים, ו-`400` שחסרים שדות.
- `db.js` מרכז את המערכים ואת יצירת המזהים, וכל משאב מקבל Router משלו.
- `POST /loans/:id/return` ולא `PATCH`: זו פעולה עסקית עם כללים משלה (אי אפשר להחזיר פעמיים), ולא עדכון חופשי של שדות.
