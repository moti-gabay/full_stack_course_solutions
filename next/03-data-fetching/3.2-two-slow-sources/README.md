# תרגיל 3.2 · שני מקורות איטיים

שני מקורות מדומים, "מזג אוויר" (2 שניות) ו"חדשות" (4 שניות), מוצגים בשלוש גרסאות, כל אחת בנתיב משלה:

| נתיב | גרסה |
| --- | --- |
| `/serial` | `await` אחרי `await` בתוך הדף |
| `/parallel` | `await Promise.all([...])` בתוך הדף |
| `/streaming` | כל רכיב ב-`<Suspense>` משלו עם skeleton |

## הרצה

```bash
npm install
npm run build && npm start   # המדידות נעשו במצב production
```

פותחים את `http://localhost:3000` ועוברים בין שלושת הקישורים.

## משתני סביבה

אין.

## מדידה

נמדד מול `npm start` על המחשב המקומי, עם סקריפט Node שקורא את התשובה כ-stream. הסקריפט רושם מתי הגיע הבייט הראשון ומתי הגיע ה-HTML של כל רכיב. שתי הרצות לכל גרסה:

| גרסה | משהו מוצג (first byte) | מזג אוויר מוצג | חדשות מוצגות | הכל מוצג |
| --- | --- | --- | --- | --- |
| בטור (`/serial`) | 6.48 / 6.57 שנ' | 6.48 / 6.57 | 6.48 / 6.57 | 6.54 / 6.59 שנ' |
| `Promise.all` (`/parallel`) | 4.21 / 4.18 שנ' | 4.21 / 4.18 | 4.21 / 4.18 | 4.25 / 4.20 שנ' |
| streaming (`/streaming`) | 0.42 / 0.14 שנ' | 2.40 / 2.13 | 4.40 / 4.13 | 4.42 / 4.15 שנ' |

מסקנות:

- **בטור**: המקור השני מתחיל רק אחרי שהראשון הסתיים, כלומר 2+4=6 שניות. עד אז המשתמש רואה מסך לבן.
- **`Promise.all`**: שני המקורות רצים במקביל, והדף מחכה לאיטי מביניהם, כ-4 שניות. הזמן הכולל שווה ל-streaming, אבל עד שהכל מוכן לא מוצג כלום.
- **streaming**: הכותרת והשלדים מגיעים מיד, תוך פחות מחצי שנייה. מזג האוויר מחליף את השלד שלו אחרי כ-2 שניות, והחדשות אחרי כ-4. זה אותו זמן כולל כמו `Promise.all`, אבל זמן התגובה הנתפס טוב בהרבה.

## החלטות מרכזיות

- **`await connection()` בתוך המקור המדומה**. בלי השורה הזו, ב-Cache Components ה-`setTimeout` היה רץ פעם אחת בזמן ה-build, והתוצאה הייתה נשמרת ב-HTML הסטטי. כך לא היה מה למדוד. `connection()` מסמן שהעבודה צריכה לרוץ בכל בקשה.
- **ב-`/streaming` הדף עצמו לא `async`**. רק הרכיבים `Weather` ו-`News` מחכים, וכל אחד עטוף ב-`<Suspense>` נפרד. לכן כל אחד מוצג ברגע שהוא מוכן, בלי לחכות לשני. בפלט ה-build הנתיב מסומן `◐` (Partial Prerender): המעטפת והשלדים נבנים מראש, והתוכן מוזרם בזמן הבקשה.
- **ב-`/serial` וב-`/parallel` יש `export const instant = false`**. עם Cache Components, ‏Next דורש שלכל דף יהיה static shell, ודף שמחכה בראשו בלי Suspense נכשל ב-build. כאן החסימה מכוונת כדי שאפשר יהיה להשוות, ולכן ביטלנו את הבדיקה רק לשני הדפים האלה. הם מסומנים `ƒ` (Dynamic). באפליקציה אמיתית לא עושים את זה.
- **שכבת הנתונים ב-`lib/data.ts` משותפת לשלוש הגרסאות**. ההבדל ביניהן הוא רק המקום שבו מחכים לנתונים, וזה בדיוק מה שהתרגיל בא להראות.
