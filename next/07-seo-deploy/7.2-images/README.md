# תרגיל 7.2 · תמונות

גלריה של 7 תמונות (תמונה ראשית ועוד 6 בגריד) בשתי גרסאות, כדי שאפשר יהיה להשוות:

- `/before`: `<img>` רגיל שמצביע על קובצי ה-JPEG המקוריים (1920×1280).
- `/`: אותה גלריה עם `next/image`.

## הרצה

```bash
npm install
npm run build && npm start   # http://localhost:3000 ו-http://localhost:3000/before
```

מודדים במצב production. ב-`npm run dev` התמונות לא נשמרות ב-cache באותה צורה, והמספרים לא מייצגים.

## משתני סביבה

אין.

## החלטות מרכזיות

- **ייבוא סטטי של התמונות** (`import p10 from "@/public/photos/photo-10.jpg"` ב-`lib/photos.ts`): Next קורא את הרוחב והגובה ב-build. אין צורך לכתוב `width`/`height` ידנית, השטח נשמר מראש (בלי layout shift), ו-`placeholder="blur"` עובד בלי הגדרות נוספות.
- **`sizes` לפי ה-layout האמיתי:** הגריד הוא עמודה אחת בנייד, שתיים מ-`sm` (640px) ושלוש מ-`lg` (1024px), ולכן `sizes="(max-width: 640px) 100vw, (max-width: 1024px) 50vw, 33vw"`. לתמונה הראשית, שרוחבה לכל היותר `max-w-6xl`: `sizes="(max-width: 1152px) 100vw, 1152px"`. בלי `sizes`, הדפדפן מניח `100vw` ומוריד תמונה גדולה מדי.
- **`loading="eager"` (ו-`fetchPriority="high"`) רק לתמונה הראשית:** היא מעל הקפל ולכן נטענת מיד. שאר התמונות נשארות ב-lazy, ברירת המחדל. ב-Next 16 `priority` הוצא משימוש, ומשתמשים ב-`loading="eager"` או ב-`preload`.
- **פורמט:** `next/image` מגיש WebP כברירת מחדל, גם כשהמקור JPEG.
- **`prefetch={false}` על הקישורים בין שתי הגרסאות:** בלי זה, ה-`<Link>` ל-`/before` טוען מראש את קובצי ה-JPEG המקוריים של אותו דף, ומשקל `/` בהשוואה יוצא גבוה בטעות (במדידה הראשונה זה הוסיף כ-2.5MB).

## השוואת משקל העמוד

נמדד עם Chromium headless (Playwright דרך CDP), בלי cache, אחרי `npm run build && npm start`. גללנו לסוף הדף כדי שגם התמונות שנטענות ב-lazy ייספרו. המספרים הם הבייטים שהועברו ברשת.

| מסך | גרסה | כל העמוד | תמונות | פורמט | רוחב התמונה הראשית שנבחר |
| --- | --- | --- | --- | --- | --- |
| נייד 375px @2x | לפני (`<img>`) | 2,710KB | 2,513KB | JPEG | 1920 (המקור) |
| נייד 375px @2x | אחרי (`next/image`) | 614KB | 409KB | WebP | 750 |
| טאבלט 768px @1x | לפני | 2,710KB | 2,513KB | JPEG | 1920 |
| טאבלט 768px @1x | אחרי | 361KB | 156KB | WebP | 828 |
| דסקטופ 1440px @1x | לפני | 2,710KB | 2,513KB | JPEG | 1920 |
| דסקטופ 1440px @1x | אחרי | 581KB | 377KB | WebP | 1200 |

**מסקנות:**

- משקל התמונות ירד פי 6 עד 16, לפי רוחב המסך.
- ברוחב מסך אחר נטען גודל אחר של אותה תמונה: התמונה הראשית ב-750, 828 או 1200 פיקסלים.
- הנייד מוריד יותר מהטאבלט, כי ב-DPR 2 הוא צריך פי 2 פיקסלים, ובטאבלט הגריד כבר בשתי עמודות.
- בגרסת "לפני" כל מכשיר מוריד את אותם 2.5MB.

את המספרים אפשר לראות גם בעצמכם: DevTools ← Network ← סינון Img ← Disable cache, ומשווים את השורה התחתונה (transferred) בין `/before` ל-`/`.

## על התמונות

שבע תמונות מ-picsum.photos (מזהים קבועים, 1920×1280), כ-2.5MB ב-`public/photos`.
