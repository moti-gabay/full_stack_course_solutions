# תרגיל 2.3 · חיפוש דרך ה-URL

הדף קורא את `searchParams` ומסנן את המתכונים בשרת. שדה החיפוש (Client Component) מעדכן את `?q=` בכתובת עם `useRouter`, אחרי debounce של 400ms. רענון או שיתוף הקישור שומרים את החיפוש.

## הרצה

```bash
npm install
npm run dev
```

מקלידים "פסטה" בשדה: הכתובת משתנה ל-`/?q=פסטה` פעם אחת אחרי שמפסיקים להקליד, ובטרמינל מופיע `[server] filtering recipes, q="פסטה"`.

## משתני סביבה

אין.

## החלטות מרכזיות

- **ה-URL הוא ה-state.** החיפוש לא נשמר ב-`useState` אלא ב-`?q=`, ולכן רענון, Back ושיתוף קישור מציגים את אותן תוצאות בלי קוד נוסף.
- **הסינון בשרת:** `Results` היא Server Component שעושה `await searchParams` ומסננת. הלקוח רק משנה את הכתובת, ו-Next מביא מהשרת את התוצאות החדשות.
- **debounce:** כל הקשה מבטלת את הטיימר הקודם (`clearTimeout`) ומתחילה טיימר חדש, ולכן `router.replace` נקרא רק אחרי הפסקה. משתמשים ב-`replace` ולא ב-`push`, כדי שכל חיפוש לא יוסיף רשומה להיסטוריה. הטיימר שמור ב-`useRef`, כי הוא לא משפיע על הרינדור.
- **שדה לא מבוקר (`defaultValue`):** הערך ההתחלתי מגיע מ-`useSearchParams`, ומשם הדפדפן מנהל את השדה. כך אין קפיצות בזמן הקלדה כשהכתובת מתעדכנת.
- **Suspense עם Cache Components:** גם `searchParams` בשרת וגם `useSearchParams` בלקוח הם נתוני בקשה. כל אחד עטוף ב-`<Suspense>`, ולכן הכותרת נבנית מראש כ-static shell והדף מסומן `◐` (Partial Prerender) בפלט ה-build. בלי ה-Suspense ה-build נכשל.
