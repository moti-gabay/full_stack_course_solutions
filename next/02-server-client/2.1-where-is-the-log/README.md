## איפה כל לוג מופיע (נבדק בפועל)

| לוג | טרמינל ב-`npm run dev` | קונסול הדפדפן ב-dev | `npm run build` | טרמינל ב-`npm start` | קונסול הדפדפן ב-production |
| --- | --- | --- | --- | --- | --- |
| `[server] HomePage rendered` | כן, בכל רענון | כן, עם תגית "Prerender" (העתק שמשודר מהשרת) | כן, פעם אחת | לא | לא |
| `[client] Counter rendered` | כן, בכל רענון | כן, בטעינה ובכל לחיצה (פעמיים כל פעם) | כן, פעם אחת | לא | כן, בטעינה ובכל לחיצה |

למה:

- **קומפוננטת שרת** רצה רק בשרת. הקוד שלה לא נשלח לדפדפן בכלל, ולכן הלוג מודפס בטרמינל. ב-dev, ‏Next מעביר את הלוגים של השרת גם לקונסול של הדפדפן, עם תגית, כדי שיהיה נוח לדבג. זה העתק ולא ריצה בדפדפן, ובפרודקשן זה לא קורה.
- **קומפוננטת לקוח** רצה בשני מקומות: פעם בשרת, כדי לייצר את ה-HTML הראשוני (SSR או prerender), ושוב בדפדפן ב-hydration ובכל רינדור מחדש. לכן הלוג שלה מופיע גם בטרמינל וגם בקונסול. לחיצה על המונה משנה state בדפדפן בלבד, ולכן הלוגים של הלחיצות מופיעים רק בקונסול.
- **ב-dev כל לוג של לקוח מופיע פעמיים** בגלל React Strict Mode, שמרנדר כל קומפוננטה פעמיים כדי לחשוף side effects. בפרודקשן מופיע לוג אחד.
- **בפרודקשן הדף סטטי** (`○` בפלט ה-build): עם Cache Components, דף בלי נתוני runtime נבנה פעם אחת ב-`npm run build`. לכן שני הלוגים של השרת מודפסים בזמן ה-build, ו-`npm start` מגיש HTML מוכן בלי להריץ את הקומפוננטות בכלל.

## החלטות מרכזיות

- `"use client"` רק בקובץ של המונה, כי הוא היחיד שצריך `useState` ו-`onClick`. הדף נשאר Server Component.
- `"use client"` לא אומר "רץ רק בדפדפן". זה אומר "הקוד נשלח לדפדפן ועובר hydration", ובנוסף הוא מרונדר בשרת ל-HTML.
- כדי לדעת איפה קוד רץ, צריך לבדוק גם ב-dev וגם ב-build: ב-dev כל בקשה מרנדרת מחדש, ובפרודקשן דף סטטי לא מרונדר בכלל בזמן בקשה.
