# תרגיל 4.1 · לראות את ה-cache

דף עם שני רכיבים שמציגים את השעה שבה נוצרו. רכיב אחד מסומן `"use cache"`, והשני לא שמור ב-cache.

## הרצה

ה-cache מתנהג כמו שצריך רק ב-production (ב-`npm run dev` הכל מתרנדר מחדש בכל בקשה):

```bash
npm install
npm run build && npm start   # http://localhost:3000
```

מרעננים את הדף כמה פעמים ומשווים בין שתי השעות.

## משתני סביבה

אין.

## בדיקת `next.config.ts`

`create-next-app` עם ברירות המחדל כבר מפעיל את Cache Components:

```ts
const nextConfig: NextConfig = {
  cacheComponents: true,
  partialPrefetching: true,
  ...
};
```

## תיעוד: מה משתנה בכל רענון

שלוש טעינות של הדף בדפדפן, בהפרש של כ-4 שניות, אחרי `npm run build && npm start` (ה-build הסתיים ב-14:42:10):

| זמן הטעינה | רכיב עם `"use cache"` | רכיב בלי cache |
| --- | --- | --- |
| 14:42:15 | 14:42:10 | 14:42:16 |
| 14:42:19 | 14:42:10 | 14:42:20 |
| 14:42:23 | 14:42:10 | 14:42:24 |

- **הרכיב עם `"use cache"` לא משתנה**. השעה שלו היא השעה שבה רץ ה-build: הוא רונדר פעם אחת בזמן ה-prerender, והתוצאה נשמרה בתוך ה-HTML הסטטי. הוא יחושב מחדש רק לפי `cacheLife("hours")`, כלומר אחרי שעה, בבקשה הבאה ברקע.
- **הרכיב בלי cache משתנה בכל רענון**. הוא קורא ל-`await connection()`, ולכן רץ בכל בקשה ומציג את שעת הבקשה.
- בפלט ה-build הדף מסומן `◐` (Partial Prerender), עם Revalidate של 1h. החלק השמור והמעטפת הם HTML סטטי, ובמקום הרכיב החי נשמר ה-fallback "טוען...", שמוחלף בזמן הבקשה.

## החלטות מרכזיות

- **`"use cache"` ברמת הקומפוננטה**, ולא על כל הדף. כך אפשר לראות על אותו מסך את שני המצבים זה לצד זה.
- **`cacheLife("hours")` לצד `"use cache"`**, לפי ההמלצה ב-docs לתת לכל cache אורך חיים מפורש. בלי זה חל פרופיל `default` (חידוש כל 15 דקות).
- **הרכיב החי עושה `await connection()` ועטוף ב-`<Suspense>`**. עם Cache Components, ‏`new Date()` בלי cache ובלי סימון של זמן בקשה נכשל ב-build. Next לא יודע אם הכוונה לשעת ה-build או לשעת הבקשה, ו-`connection()` אומר במפורש: "שעת הבקשה".
