# תרגיל 5.2 · ולידציה ושגיאות

טופס הרשמה עם ולידציה ב-Zod בצד השרת. `useActionState` מציג שגיאה ליד כל שדה ושומר את מה שהוקלד, וכפתור עם `useFormStatus` מציג "שומר...".

## הרצה

```bash
npm install
npm run dev
```

ב-http://localhost:3000 שולחים את הטופס עם שם של תו אחד, אימייל לא תקין או גיל מתחת ל-18, ורואים שגיאה ליד כל שדה. ב-action יש השהיה של שנייה, כדי שיהיה אפשר לראות את "שומר...".

**בדיקת עקיפה של הדפדפן:** ב-DevTools מוחקים את `required` ואת `type="email"` מהשדות ושולחים: השרת עדיין מחזיר את השגיאות. אפשר גם לשלוח POST ישירות בלי דפדפן (בדקתי עם `curl`, עם השדות `name=a`, `email=bad` ו-`age=5`): התשובה כללה את שלוש הודעות השגיאה, והשדה חזר עם `value="bad"`.

אין.

## החלטות מרכזיות

- **הוולידציה בשרת היא זו שקובעת**: `required` ו-`type="email"` בדפדפן רק משפרים את חוויית המשתמש, ואפשר לעקוף אותם בקלות. ה-action מריץ `schema.safeParse` על כל בקשה, כי כל אחד יכול לשלוח POST ישירות.
- **`z.flattenError(error).fieldErrors`** (Zod 4) הופך את השגיאה לאובייקט `{ name: [...], email: [...] }`, כך שכל שדה מציג את השגיאה שלו.
- **ה-action מחזיר גם את `values`**: ב-React 19, אחרי ש-action של טופס מסתיים, הטופס מתאפס. בזכות `defaultValue={state.values.x}` הוא מתאפס בחזרה לערכים שהמשתמש הקליד, ולא לשדות ריקים.
- **`useFormStatus` בקומפוננטה נפרדת (`SubmitButton`)**: ה-hook מחזיר את המצב של ה-`<form>` שעוטף אותו, ולכן הוא חייב לשבת בתוך הטופס ולא באותה קומפוננטה שמרנדרת את ה-`<form>`.
- **רק `register-form.tsx` מסומן `"use client"`**: הדף עצמו נשאר Server Component, וה-action מיובא מקובץ `"use server"`.
