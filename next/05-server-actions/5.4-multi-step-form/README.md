# תרגיל 5.4 · טופס רב-שלבי

אשף של 3 שלבים להוספת מתכון: פרטים, מצרכים ותמונה. השרת מאמת כל שלב, התמונה נשמרת בדיסק, ובסיום יש `redirect` לדף המתכון. ההרשאה נבדקת בתוך ה-action עצמו.

## הרצה

```bash
npm install
cp .env.example .env.local   # ומחליפים את SESSION_SECRET במחרוזת אקראית
npm run dev
```

1. נכנסים ל-http://localhost:3000/login ומתחברים עם `dana` / `1234` (משתמש לדוגמה שמוגדר בקוד).
2. ב-`/new` עוברים את שלושת השלבים. בסיום יש הפניה ל-`/recipes/<id>`.

המתכונים נשמרים ב-`data/recipes.json` והתמונות ב-`uploads/`. שתי התיקיות נוצרות בשימוש הראשון ונמצאות ב-`.gitignore`.

## משתני סביבה

| משתנה | משמעות | דוגמה |
| --- | --- | --- |
| `SESSION_SECRET` | המפתח לחתימת ה-cookie של ההתחברות (HMAC) | `replace-with-a-long-random-string` |

## החלטות מרכזיות

- **action אחד לכל השלבים, עם `useActionState`**: ה-state מחזיק את מספר השלב, את הערכים ואת השגיאות. השרת הוא שמחליט אם עוברים שלב: הוא מחזיר `step + 1` רק כשהוולידציה עברה.
- **השרת לא סומך על השלבים הקודמים**: הערכים משלבים קודמים עוברים בשדות hidden, ולכן אפשר לזייף אותם. בכל שליחה ה-action מריץ מחדש את כל הסכמות עד השלב הנוכחי, כך שבקשה שטוענת "אני בשלב 3" עם שדות ריקים חוזרת לשלב 1 עם שגיאות.
- **בדיקת ההרשאה בתחילת ה-action**: הדף `/new` מציג את האשף רק למשתמש מחובר, אבל זו רק נוחות. Server Action הוא endpoint של POST שכל אחד יכול לקרוא לו, ולכן הבדיקה האמיתית היא `getUser()` בתוך `wizardStep`.
- **cookie חתום עם HMAC**: ה-cookie הוא `dana.<חתימה>`. בלי `SESSION_SECRET` אי אפשר לייצר חתימה תקינה, ולכן cookie מזויף (`session=dana.forged`) נדחה. ההשוואה נעשית עם `timingSafeEqual`.
- **תמונות ב-`uploads/` ולא ב-`public/`**: `next start` מגיש רק קבצים שהיו ב-`public` בזמן ה-build. לכן ההעלאות מוגשות דרך Route Handler (`app/uploads/[name]/route.ts`) שמקבל רק שמות בפורמט שהשרת עצמו יצר, כדי למנוע path traversal.
- **`bodySizeLimit: "3mb"`** ב-`next.config.ts`: גוף של Server Action מוגבל כברירת מחדל ל-1MB. התמונה מוגבלת ל-2MB ב-Zod, ונשאר עוד מקום ל-overhead של multipart.

## הדגמה: קריאה ל-action בלי הרשאה

Server Action נקרא בבקשת POST רגילה. שלחתי בקשות ישירות עם `curl` (במצב production, `npm run build && npm start`), עם אותם שדות שהטופס שולח: מזהה ה-action מהשדות המוסתרים, `step`, `title` וכו'.

| בקשה | מה נשלח | מה חזר |
| --- | --- | --- |
| בלי cookie | `step=1`, `title=שקשוקה`, `description=ביצים ברוטב עגבניות` | הדף חזר עם ההודעה **"נדרשת התחברות"**, ושום דבר לא נשמר |
| cookie מזויף | אותו דבר, עם `Cookie: session=dana.forged` | **"נדרשת התחברות"**: החתימה לא תואמת |
| מחובר, עקיפת שלבים | `step=3` עם תמונה, אבל `title`, `description`, `ingredients` ו-`prepMinutes` ריקים | חזרה ל-**"שלב 1 מתוך 3"** עם "כותרת של לפחות 3 תווים" |
| מחובר, נתונים תקינים | `step=3` עם כל השדות ותמונת PNG | `303 See Other`, `Location: /recipes/<id>`; המתכון נשמר עם `owner: "dana"` והתמונה מוגשת ב-`/uploads/<id>.png` (`200 image/png`) |

המסקנה: הסתרת הטופס ממשתמש לא מחובר לא מגינה על כלום. ההגנה היא הבדיקה בתוך ה-action.
